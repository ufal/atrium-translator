### Status update — code side done (By Opus)

`c24f5bc` answers the big question as a **switch**, not a verdict: `--output-mode replace|append`
(also `config.txt`, `OUTPUT_MODE`, and a field on `/translate`). `replace` stays the default, with
output byte-identical to before across all 16 shipped samples.

Append uses AMCR's own convention — same tag, distinguished by `xml:lang`, as the thesaurus already
does for `heslo` / `heslo_en`:

```xml
<amcr:nazev xml:lang="cs">Davle - kultovní areál 1 - klášter sv. Jana Křtitele na Ostrově</amcr:nazev>
<amcr:nazev xml:lang="en">Davle - ritual site 1 - monastery St. John the Baptist on the Island</amcr:nazev>
```

ALTO **labels rather than duplicates** — per-`String` append would multiply a fabricated word-to-box
alignment. Also fixed: `/translate` returned HTTP 200 with metadata untranslated, and the batch
fallback degraded ~20× in call count behind a silent `except: pass`. CI green, 592 tests.

**The AMCR `maxOccurs` question is no longer a blocker** — it is one command:
`--output-mode append --xsd https://api.aiscr.cz/schema/amcr/2.2/amcr.xsd`. A validation failure
there is the answer.
