## 🎯 Goal

With `source_lang=auto`, a segment that the identifier confidently places in a language the backend cannot translate must not be sent to the Czech model in silence. Either the caller is told (count and languages), or the segment keeps its source text and is logged `untranslated`, the way a degenerate reply is.

The fallback for *untrustworthy* guesses stays as it is. It was built (#46) to stop FastText's `krc`/`yue`/`bod` answers on short OCR blocks from becoming source languages.

## 🔎 What the code does today (`ef3b311`)

**The resolution order** (`processors/language.py:1-25`, `resolve_source_language()` at `:264-289`):
1. **detected:** at least `LANG_ID_MIN_LETTERS` (20) letters, a candidate scoring at least `LANG_ID_MIN_CONFIDENCE` (0.5), *and* `policy.accepts(lang)`;
2. **hint:** the element's own label;
3. **context:** the document's language;
4. **default:** `DEFAULT_SOURCE_LANG`, else `cs`.

`accepts()` (`:166-171`) allows the default and the backend's translatable set. `allowed_source_languages()` (`:207-237`) builds that set:
- LINDAT exposes model pairs (`supported_models = ["cs-en", "de-en", …]`), so its set is the languages paired with the target;
- other backends answer `supported_languages()`;
- `None` means no restriction.

**Two different cases end on the same path:**
- a low-score or exotic guess on a short OCR block (the case the policy was built for);
- a confident detection of a real language the backend lacks: Latin `la` 0.97, Hungarian `hu` 0.99. The `for` loop at `:278-283` skips the candidate because `accepts()` is false, the hint and context fall through, and the segment gets `Resolution("cs", "default", raw=("la", 0.97))`.

In a stub-identifier run, German stays `de` (LINDAT has `de-en`).

**Where it surfaces:**
- **The log.** `LanguageTally` (`:292-316`) counts each resolution and every raw guess that was not used. `utils._SourceLanguages.log()` (`utils.py:416-432`) writes one line per document, at WARNING when anything was overridden: `…; FastText guesses not used: la×1, hu×1`.
- **The CSV.** The `_log.csv` row is `[doc_id, "", xpath, source, translation, status]` (`utils.py:852`). Its statuses are `ok`, `rerun`, `approx_alignment`, `untranslated` (`utils.py:208-218`); a fallback is logged `ok`.
- **The service** discards the CSV (`utils.py:759`, "which the service discards").
- **The record's `translations` block** gets `detected_source_lang` (the document's language) only (`utils.py:412-414`).
- **The paradata** gets the policy (`SourceLanguagePolicy.describe()`, `:198-205`), not what it did.
- **`limits_applied`** says nothing.

**The precedent for option (b).** A field still degenerate after the re-run keeps its source text, is logged `untranslated` and is noted in `limits_applied` as `TRANSLATION_RERUN_ROUNDS`, effect `skipped` (`utils.py:759-765`; ALTO lines `utils.py:1446-1457`).

**The contract limits option (a).** A `limits_applied` entry must name an `/info` limit key and one of the shared effects:
- the effects are `sampled`, `split`, `trimmed`, `skipped`, `stopped` (`atrium_limits.EFFECTS`, `atrium_limits.py:65`; `LimitNote`, `service/atrium_service.py:533-542`);
- none of them describes "translated from another language".

"The source text was kept" is `skipped`. So (b) fits the existing contract; (a) does not without a change to the hub-shared modules.

**Tests.**
- `tests/test_language.py` has an identifier double (`_Candidates`, `:48-57`) and the policy's cases: `test_an_untranslatable_guess_is_never_used` (`:134`), `test_without_context_the_default_applies` (`:160`), `test_tally_reports_what_was_overridden` (`:179`).
- No test asserts what a caller sees.

## 🧵 Related

- **#46:** the LINDAT production recipe, run with `cs` explicitly. **#4:** the bake-off. EuroLLM and MADLAD (`ct2`) translate Latin and Hungarian, so with those backends `accepts()` is true and this case does not arise.
- [atrium-project#53](https://github.com/ufal/atrium-project/issues/53) (where found), [atrium-project#32](https://github.com/ufal/atrium-project/issues/32) (the `limits_applied` contract).

## 🔑 Decision open

**(a) report it, or (b) refuse it per segment.**
- **Recommended: (b).** Keep the source text, log `untranslated` with a reason, and note it in `limits_applied` with effect `skipped`.
- **Why:** it is honest output, and it reuses the degenerate-reply path and its note. Translating Latin with the Czech model yields plausible nonsense that a reader cannot tell from a translation.
- **Fallback stays:** a guess below the threshold, or under 20 letters, still falls back as today.
- **Which limit the note names.** A declared limit is needed. Proposed: `LANG_ID_MIN_CONFIDENCE` becomes an `/info` limit, because it is the threshold that decided the case: a candidate at or above it is a detection, not a guess.

## ✅ Done when

With a stub identifier returning `la` 0.97 / `hu` 0.99 and a stub LINDAT:
- both segments keep their source text, and the CSV says `untranslated` with the guessed language;
- the response's `limits_applied` carries one note with count 2 that names `la` and `hu`;
- a German segment is translated as before;
- a short or low-score guess still falls back to the document language;
- the README's language section says which of the two happens, and when.
