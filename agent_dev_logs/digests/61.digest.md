## 🧭 2026-11-16 — why the depiction misled

- **The contract (D34, §8):** the field list belongs to AMČR and comes with each request; the translator has no
  default list; in metadata mode it refuses a request without one.
- **Already right before the change:** `README.md:23-26`, `config.txt:34-36`, `docs/configuration.md:72-73`,
  `docs/usage.md:116`, `docs/reference/cli.md:24`, `service/README.md:103` called it an example; no code loaded it
  (`eval/bakeoff.py:718`, a research tool, was the only default); it was not shipped (`.dockerignore:42-43`,
  `release.yml:160`).
- **What misled:**
  - the name `amcr-fields.txt`, and no header in the file: opened on its own, it read as *the* AMČR list;
  - `README.md:57-59` and `docs/usage.md:338-342` ran `--xpaths amcr-fields.txt` **inside the published image**,
    which does not contain it: the command failed, and suggested the image bundles the list;
  - in the hub: `docs_site/workflows/translator.md:158` ("the image carries … the AMČR field list"),
    `docs_site/external-tools.md:63-64`, `docs/k8s_acceptance_runbook.md:247,254-256`; ALTO and full-text translation
    shown as a pipeline stage (`docs_site/pipelines.md:134,141,163,211`, `docs_site/index.md:136,140`,
    `docs_site/workflows/translator.md:128-136`, `docs_site/glossary.md:51`);
  - the Galaxy wrapper `galaxy/tools/atrium_translator/translator.xml:60,104,176` passed `/app/amcr-fields.txt` as
    "the bundled list", present in its pinned `1.7.8-beta` image but in no image from v2.0.

  runs); older CONTRIBUTING rows; `agent_dev_logs/`.
